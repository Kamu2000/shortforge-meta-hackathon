## 2026-10-29 - render-correctness block: layout law, caption alignment, the F1-F7 verifier

- **`src/spatial_director/layout_law.py`** - hook and caption placement computed FROM the decoded head geometry (this replaces the compositor's manual `--hook-y-frac`, which remains only as an override; the layout output now feeds the compositor call path). Hook: candidate centre bands are scored against the speaker's occupancy in the hook window; the winner is the in-safe-zone candidate nearest the preferred 0.30 fraction whose predicted glyph occlusion is <= 25%. Occupancy for scoring is deliberately conservative (evaluation steer, same day): the head band is dilated by a 12px guard and treated as solid, because the feathered matte edge is exactly where placement decisions bite (see the ghosting follow-up below). Captions: a fixed two-line block in the lower safe zone; the planner JUMPS the block's bottom edge to the highest face top among the frames its cues overlap (creeping the block up fails - overlap grows before it clears); infeasible cases keep the least-overlap position and report `feasible=False` rather than hiding it. Two renderer traps were found by tests and are handled in the layout path, not the compositor: the compositor's default width budget lets glyph ink reach x=43..1037, and a single long word ("REHEARSES" at the default size) overflows any width budget because the renderer shrinks for line count, not width - the layout path renders at the safe width minus a stroke guard, steps the font size down until the INK fits, and re-centres on the safe zone's centre (x=520, not the canvas's 540).

## 2026-10-29 - rescue loop + pipeline land; first full run stops on a frame-count mismatch

- **`src/spatial_director/rescue_loop.py`** - the model-driven repair loop (Agents-102 shape: feedback is the receipt's check id + measured + threshold; the repair is chosen from a FIXED menu in code, never free-form). Spark 1.3 (ledger-gated) receives the failed checks with measured values, the applicable menu subset, the current hook and a transcript excerpt, and picks ONE repair as strict JSON: TRIM_SILENCE (F5: cut over-long pauses from the render, keep 0.30s of each gap, retime captions through the cut map), REPOSITION_HOOK (F2: re-plan at half the occlusion cap), REFIT_HOOK_INK (F3: re-render the hook through the layout path so ink fits the safe zone), RESCALE_SPEAKER (F4: 0.92x via padded source-space inputs so render and verifier geometry stay identical), REGENERATE_HOOK_TEXT (F1/F6/F7: new Spark hook line, validated for word/content counts). A pick outside the menu, a pick targeting a passing check, an unparseable reply, or a failed check with no menu entry = NO repair; the draft-1 FAIL stands with the reason recorded. Repairs execute from cached artifacts only - the module contains no SAM client and cannot re-buy segmentation (a test asserts this from the source). The repaired render is re-verified with the full F1-F7 + Wonder, and the output is a chained receipt: draft-1 verdict -> repair (menu id, Spark's stated reason, Spark call cost/request id, any extra calls) -> draft-2 verdict. ONE repair max, hard-coded by structure. The shared render path (`render_composite_with_captions`: composite frames + caption layer in front, audio muxed) lives here and serves draft 1 and repairs alike. 15 tests with injected fakes: menu enforcement, the one-repair cap, TRIM executed on a real WAV with a 0.8s gap (frames and retimed cues asserted), not-applicable TRIM on continuous tone, all five executors, chained-receipt JSON shape.

## 2026-10-31 — Standalone receipt re-verifier + hash chain (`tools/reverify.py`)

**What it is.** A standalone CLI that lets anyone with a receipt and its run evidence re-verify the receipt WITHOUT the pipeline, WITHOUT model calls, and WITHOUT re-rendering: `python3 tools/reverify.py RECEIPT.json [--artifact FILE] [--evidence-dir DIR] [--artifact-dir DIR] [--json]`. The tool prints its honest boundary on every run: Wonder judgement legs are recorded, not re-judged; the promise is hash-verification + deterministic re-measurement, NEVER bit-identical re-rendering (Voice Transcribe and SAM are not bit-deterministic).

**The hash chain.** Every draft's `inputs_sha256` block is recomputed from disk — including, correctly, `inputs_sha256.video`, which IS the sha256 of the artifact file at verify time (a finding of this build: the brief's scope item 1 assumed artifact hashes might not be recorded; they are, and the tool verifies them). Also checked: the SAM response file hash and the caption-list hash (sha256 of the cue JSON). Structural checks: sequential draft numbering, top-level artifact == last draft's artifact, repair consistency (executed → first draft failed the target check, final draft passes it, verdict PASSED_AFTER_REPAIR; not_needed → PASSED_FIRST_DRAFT). The folded fingerprint itself is computed, not compared — the per-draft hashes are what are verified.

**Deterministic re-measurement.** The tool re-runs the verifier's own `verify()` on inputs rebuilt from the receipt + run evidence (window clip, SAM response, captions, trimmed stem) and compares each recorded measured value within stated tolerances (ratios 0.005, dB 0.25, seconds 0.02, presence 0.02, centroid 0.1, ints/px exact). A single AAC encode then muxes the corrected WAV back over the stream-copied video, the MP4 is measured, and up to 3 post-encode corrections (limiter ceiling set from the *measured* encode overshoot; exact gain or cut for the integrated leg) are muxed and re-measured the same way. The loop is bounded; if both legs still have not landed, the best measured artifact is returned and the draft-2 FAIL stands. The detail string reports the numbers measured on the returned file. The speech stem is still never touched, and the video stream is still bit-identical (stream-hash asserted in tests).
